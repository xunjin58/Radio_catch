# 交接说明

## 当前可用范围

- 后端本地 API 覆盖健康检查、模型配置、项目级业务背景、素材导入/按需处理、素材审核、AI 混剪规划、实验/成片、任务、指标导入和分析。
- 素材理解为 MiMo 优先：导入只读取文件头元数据，先将原视频直接交给 MiMo；MiMo 失败时才使用 FFmpeg 全量解码诊断本地源文件。非原生模型或人工排查需要关键帧时，显式调用素材处理接口。
- 已实现文案先行（Script-First）链路：素材能力词表写入 `tags.shot_capabilities`，`script_facts` 驱动 planner 逐条 EDL 覆盖校验，后期 manifest 保存 `fact_evidence_mapping` 与 `product_facts`。本轮目标素材已由用户确认画面审核通过；成片级 MiMo 看片保留为可选复核，不再是文案前置。
- 前端已接入真实 API：素材库筛选、审核写回、带货镜头角色修正、多模态规划预览与确认导出、成片下载、CSV 回传、规律查询、模型配置和商家业务背景均可从界面完成。

## 已知边界

- V1 不自动登录或发布抖音，不管理多账号。
- 前端不再使用演示素材或虚构统计数据；个别高级能力（时间线拖拽编辑、批量审核、模型配置编辑/删除）仍可通过 API 使用，尚未提供对应界面。
- OpenAI 兼容模型使用显式生成的关键帧；启用原生视频能力的 Gemini 与 MiMo 配置会按其媒体限制直接发送原始视频和内嵌音轨。三种理解路径均使用项目级业务背景，且背景不能替代画面或音频证据。
- AI 混剪规划会临时发送候选摘要、标签以及已存在的封面和关键帧；模型必须返回候选素材中的实际片段 EDL，服务端会再次校验审核状态、菜品、时间范围和总时长后才可导出。
- `script_facts` 目前经 API 使用，前端尚无专门编辑入口；事实无证据时必须处理 `uncovered_facts`，不能交给 TTS。
- 媒体处理使用本进程任务池，适用于单人本地部署；若扩展到多进程或多人，应替换为持久队列与对象存储。

## 建议的下一步

1. 用文案先行规则完成 5 条新批次的起草、选片、渲染、实测时长定稿和盲听 A/B；定稿前不得进 TTS。
2. 为原生视频模型补充成本统计和真实供应商回归验证。
3. 补充 `script_facts`、时间线拖拽编辑、批量审核和模型配置编辑/删除界面。
4. 使用真实发布数据运行不少于 3 组独立对照实验后，再将候选结论升级为已验证规律。
