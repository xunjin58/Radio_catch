# Radio Catch Remix Workflow

用于把自然语言生产指令转成可审核、可追溯的混剪批次。它不是直接渲染 Skill：默认先交付候选口播，等用户确认后才进入选片和后期。

## 何时使用

用户提出“生成 N 个某品类混剪、每个不超过 T 秒”“先给我文案审核”“第 N 条通过/修改”等请求时使用。仅有素材导入或单条后期需求时，分别使用素材分析流程或 `mimo-postproduction`。

## 先决条件与批次上下文

1. 先按 [首次使用与对话流程](../../../docs/first-use-agent-guide.md) 调用 `GET /api/health` 和 `GET /api/model-configs`。若不存在 `is_active=true` 且 `protocol=mimo` 的配置，只输出“安装与启动、配置 MiMo、验证、之后怎么对话”四段式引导，并以“配置完成后告诉我”结束；不导入、不起草、不选片、不渲染。用户明确回复“配置完成”后，先测试该配置连接，再以一条小型、含音轨的受支持视频完成真实分析与人工标签审核；两者完成前仍不得进入生产。
2. 仅在首次验证已完成、用户未提出标签修订时，使用当前对话最近一次、同品类的素材批次。若该批次已经返回标签摘要，用户随后只说“生成 5 个柠檬混剪，25 秒以内”即视为标签通过；将该批素材标记为已审核后再进入文案阶段。
3. 没有可用批次、品类不一致，或用户明确要求改标签时，停在素材导入/标签审核：请用户给出素材项目文件夹和品类。不能从旧项目、商家背景或模型推断补齐素材或商品事实。
4. 用户一旦确认某项目、品类的商品卖点，连同来源保存在当前批事实池并持续复用；同一项目、同一品类的后续素材分析、文案修改和生产指令不得重复询问。只有用户明确更正/替换卖点、切换品类或现有上下文无法取得该事实池时，才说明需要更新或重新确认；绝不自行沿用到其他品类。

## 文案审核关卡（默认第一步）

收到数量与时长生产指令后，**只**输出与请求数量相同的候选口播；不创建 EDL、不生成 TTS/字幕、不渲染，也不把候选写入 `confirmed_scripts.json`。

- 多条候选时，先让子 Agent 基于每条素材能力和用户提供的参考（如有）起草；主代理审查后再输出。第一稿绝不能直接用于 TTS。
- 先读取 `backend/prompts/copywriting_xiaohongshu.md`；柠檬批次还要使用 `lemon-selling-copy`。口播必须是连续安利，不逐句解释镜头或动作。
- 仅使用“当前项目、同品类已确认卖点池＋当前批已审核素材能力”。价格、产地、口感、无籽、功效等用户确认事实必须标明来源；没有来源就不写，也不得重复向用户索取已在事实池中的内容。候选展示字段名为 `fact_assertions`；其中需要画面支撑的断言给出当前批能力依据，进入 planner 时原样映射为 `script_facts`。
- 同批的开头、价格句式、卖点推进和收尾均须不同。按约 4.5 有效字/秒估算口播时长，并留出约 0.5 秒首尾余量；目标“25 秒以内”时，候选预估须不超过 24.5 秒。成片渲染后仍须按实测时长重写，不能以预估代替验收。
- 默认小红书自然安利语气、姐妹视角、轻 CTA；禁用规则、字幕单行 ≤14 字等以文案规则文件为准。

每条按以下格式交付，状态均为“待审核”：

```text
候选 1｜待审核
预估口播：约 22 秒（有效字数：约 99）
口播：……
fact_assertions：
- <需要画面支撑的事实>：<shot_capability；当前批 clip_id 或能力汇总>
product_facts：
- <用户确认商品事实>：<确认来源>
字幕切分建议：
- <单行 ≤14 字>
```

如果没有能由画面能力支撑的商品断言，`fact_assertions` 明确写“无”；不要伪造证据。

## 审核与后续关卡

- 用户可逐条回复“第 1 条通过”，或批量回复“全部通过”。只有被明确通过的候选可以进入选片。
- 任一已通过文案发生增删改，立即回到“待审核”；重新展示该条，等待再次明确通过。
- 全部待生产文案通过后，将每条 `fact_assertions` 原样映射为 planner 的 `script_facts`。`uncovered_facts` 非空时改文案或补素材并重新审核，不能继续 TTS。
- planner 仅可选择同品类、已审核的完整原视频；每条入选素材完整播放，不能截取、加速或牺牲收尾来满足时长。组合不足时说明缺口，不硬凑数量。
- 基础 Render 成功后才调用 `mimo-postproduction`：生成连续 TTS、授权且低于人声的配乐、无底板同步字幕、完整 manifest，并回写 `Render.delivery_*`。manifest 至少包含 `video_id`、完整 EDL、脚本、字幕 cues、`fact_evidence_mapping`、`product_facts`、TTS 参数、音乐授权与音量/ducking 参数、最终媒体校验结果；用户未明确要求静音或跳过后期时，基础 Render 不是最终交付。

## 交付边界

每次回答都要清楚说明当前批次停在哪个关卡。候选文案阶段的结束语固定表达为“请审核第 N 条或回复‘全部通过’；在你确认前不会选片、生成 TTS 或渲染。”
