# 带货口播文案生成规则（Script-First · 小红书自然安利文风）

适用场景：为任意已审核商品的混剪成片编写后续接茉莉 TTS 的口播（柠檬、葡萄等均适用）。流程是：**素材能力清单 + 本批用户确认卖点池 → 自由起草连续安利 → 事实断言校验 → planner 配片并渲染 → 按实测时长精修定稿 → 用户确认 → 后期**。不再把成片级 MiMo 看片作为必经前置；`mimo_postprocess.py --analyze-only` 仍可用于交付前可选复核。

第一版草稿不得直接送 TTS；本文件是所有品类的唯一权威规则。

## 1. 风格

- 第一人称姐妹视角（茉莉女声配音；不要写“我媳妇/我老婆”）。
- 自然口语，像熟人安利、朋友分享；可有少量“呢、嘛、啊、呀”，不喊麦、不硬夸。
- 禁用“谁懂啊 / 家人们 / 救命 / 真的绝了 / 捡到宝 / 续命 / 冲吧”等夸张网感词；感叹号最多 1 个，能不用就不用。
- 用短句和长短交错的节奏，避免“此外 / 不仅…而且 / 值得注意的是”等书面词与整齐三段式排比。
- 只使用与本批商品相符、且由用户确认卖点支持的消费场景；无 emoji、话题标签或购买链接。
- 结尾是轻 CTA，不写“下单 / 买它”。

## 2. 同批差异化

同批每条的**开头、价格句式、卖点推进顺序和收尾句式**均不得复用。开头可由切面、整果、饮品成品、价格问句或可见即时动作触发，但口播要说其价值、对比或适用场景，不能复述动作；“抓眼”只在画面有合适的动作、强对比或明确主体时使用，不能硬加。

例如，一条可由可见成品或商品状态切入，再讲价格与消费场景；另一条可由用户确认的产地或发货信息切入，再讲价值对比。不要让所有稿子复用同一卖点顺序。

## 3. 卖点、能力与事实断言

每批仅可使用该批用户明确确认的卖点。价格、产地、无籽、口感、香气、发货方式等都必须记录具体来源；不能把别的品类、旧批次或业务背景自动带入本批文案。

- **事实断言**（例如大小、果粒状态、汁水、包装、饮品状态）必须标入 `fact_assertions`，并由所选切片的 `shot_capabilities` 覆盖。能力及卖点映射的唯一来源是 `backend/prompts/shot_capabilities.json`。
- 价格、产地等来自用户确认卖点池的商品事实，不要求画面能力，但必须在 `product_facts` 记录确认来源。
- 香气、口感等已确认商品事实可写成自然感官表达。这类表达不作为 `shot_capabilities`，不得仅凭画面推断，且必须在 `product_facts` 中记录确认来源。
- **禁止解说画面、镜头或动作。** 不写“我现在拿起 / 我切开 / 一刀下去 / 倒进杯子里 / 镜头一转 / 画面里有 / 园里成串的葡萄和采摘画面都在”等句子。动作和商品状态只用于审核素材能力与校验事实断言，不能成为口播内容。已确认的“现采摘现发”属于商品事实，可以写，但不能说成正在拍到的过程。
- 文案要补足画面演不出来的信息：**为什么值得、和什么比、什么时候会想吃/喝**。先完成整条连续口播，再仅将其中需要画面证明的事实断言交给 planner 做整体选片和 EDL 覆盖校验；不把口播拆成逐句分镜，也不要求情绪句、场景句、CTA 与镜头逐句锁步。
- 特定品类的表述（例如饮品名称、营养或功效）只有在用户确认并满足对应画面证据规则时才可使用；身份存疑时不猜成分。

## 4. 两段式字数预算

起草期按目标时长估算。茉莉实测约 4.3–4.8 有效字/秒（不含标点），可先按 4.5 有效字/秒估算。

配片渲染后，用**实测成片时长**重新计算：`target = 实测时长 − 0.5s`，有效字数约 `target × 4.5`。再精修定稿；20 秒只是约 100–108 有效字的参考，不能写死。最终 raw wav 时长除以 `target` 必须落在 1.08×–1.34×，超出就精简重写。

## 5. 字幕约束

- 文案可以是连续安利；字幕按标点和可读节奏拆分为 6–8 个左右的 cue。
- 每段最多 14 个可见字符、单行。字幕白字黑描边、无底板、底部居中并避开主体。

## 6. 主代理定稿检查清单

- [ ] 每个 `fact_assertions` 均有 `shot_capabilities` 证据；无证据的事实已改写或补素材
- [ ] 用户确认商品事实已记录在 `product_facts`，没有冒充为画面证据
- [ ] 情绪/场景/CTA 句不与画面矛盾，且没有重新形成句↔镜头锁步
- [ ] 没有解说镜头、画面或动作；每段都在补充价值、对比或消费场景，且会通过后期脚本的 TTS 前校验
- [ ] 同批开头、价格句式、卖点推进与收尾均不同
- [ ] 实测成片时长对应的字数预算与 TTS 1.08×–1.34× 校验通过
- [ ] 每段 ≤14 字；无 emoji、话题、书面连接词、整齐三段排比或禁用网感词
- [ ] 用户确认后才写入 `confirmed_scripts.json` 送 TTS

## 7. 与后期脚本的衔接

`confirmed_scripts.json` 兼容旧格式 `{"video_id": "口播全文"}`，也支持扩展格式：

```json
{
  "RC-xxx": {
    "script": "最终口播",
    "fact_assertions": ["汁水多"],
    "evidence": {"汁水多": {"clip_ids": ["clip-id"], "shot_capabilities": ["squeezing"]}},
    "product_facts": {"九块九两斤": "用户确认卖点池"}
  }
}
```

以 `backend/scripts/mimo_postprocess.py --batch <批次名> --scripts-json <文件>` 生成 TTS、配乐、字幕和含完整 EDL 的 manifest。
